# 最適化の具体化と実装可否（第20段階）

対象: Stellaris 4.5.2 (9776)、開発版1.39.0-dev.20。2026-10-23。

## 今回実装した内容

旧対外デバフ63種類の効果本文を削除。現在のv2はこの63種類を使用しない。既存saveを一度掃除するため、空のmodifier名だけ残す。互換定義はゲーム効果を持たず、将来互換移行を終了する版で撤去を検討する。表示名も移行中の参照用として維持する。

旧補正・旧選択flagの削除は `ngm_pressure_v2_legacy_cleanup_v20` を各国に記録して一度だけ実行する。過去の全体移行flagだけで処理を省かないため、既存dev.19 saveと後から出現した国にも適用できる。現行v2の効果量、複数国からの重複、免疫、仮想宿敵、支援効果は変更しない。

変更ファイル:

- `common/static_modifiers/NGM_modifier.txt`: 63効果本文を空の互換定義へ変更。
- `common/scripted_effects/NGM_pressure_v2_migration.txt`: 国別の一度限りの移行条件。
- `descriptor.mod`、Launcher用 `.mod`、`README.md`: dev.20と変更説明。

新規Vanilla上書きなし。NGM同名modifierを別MODが上書きする場合は競合しうる。既存saveはバックアップして更新する。新規ゲーム必須のID削除は行っていないが、旧saveの実機ロードは未確認。

## 仕組みの確認根拠

- Vanilla `common/script_values/00_script_values.txt` に `ceiling`、`floor`、`min`、`max`、`trigger:`参照の説明と例がある。注意点として `max = 50` は上限、`min = 0` は下限の指定で、一般的な関数名の直感と逆に見えるので誤用しない。
- country flagによる初回処理と、has_modifierで不足時だけ追加する方式は現在のNGMの種族国家補正等で既に使用している。
- 犯罪値参照 `planet_crime` は現行処理で使っているが、新script value内では数値取得式を現行実例またはengine資料と照合してから採用する。丸め演算の確認だけで取得式まで検証済みとはしない。
- 補正のmultiplierに集計変数を使う方式は現行v2のまま利用できる。変数同士の比較とscopeの綴りは実装時に現行例・engine資料で確定する。

## 実装単位と安全策

1. 第20段階（今回）: 旧効果廃止と一度限りの移行。
2. 次段階: 逆境の正しさ修正。圧力の変更時適用。各変更は分けて検証する。
3. 次段階: 罰金の変更時更新と惑星の移行処理。
4. その後: 巡回共通化。先に正しさを固定してから処理経路を減らす。
5. バランス・未復旧機能: 職業適性、リーダーの対象、国是併用、前衛主義、Vanilla差分。

未確認のhookを推測で追加しない。月次更新を一律に年次へ落とす案は採用しない。国是無効化後の掃除と所有者変更を省かない。技術取引・艦隊贈与は別MODなので対象外。

## 第20段階の検証

配布構造検査: 119 scriptファイル、135 event ID、parser/直接event参照/BOM検査合格。既存の圧力コア20シナリオ、UI・支援・移行53チェック合格。

専用検証では63定義が空であること、初回に旧補正を削除すること、二回目は移行本体を実行しないこと、新規国にも移行すること、現行圧力補正を維持することを実際の構文木で確認した。これは限定評価器による検証で、ゲームエンジンの実行結果ではない。

実機未確認: 空の互換定義を持つ旧saveのロード、実際のon_action発火、ロード後の通知、処理時間、AIの長期挙動。速度改善率は測定していない。
