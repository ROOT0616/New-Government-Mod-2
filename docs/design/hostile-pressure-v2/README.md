# 対外圧力イベント v2 — 4.5.2向け実装仕様

状態：実装用設計・参考コア。稼働版へ未統合。開発MODのバージョンは1.39.0-dev.17のまま。

## 決定事項

同じ効果は異なる発生国ごとに重複させる。MOD側で発生国数や合計値の上限は設けない。固定8/15枠、発生国ごとのglobal flag割当、共有global event targetを廃止する。受け手の国が現在の発生源を数え、種類ごとに合計した補正を1個ずつ持つ。

`合計補正 = 1か国あたりの基礎補正 × 条件を満たす発生国数`

同じ国を同じ種類で2回数えない。正式宿敵＋架空宿敵でも1か国分。異なる種類は併存し、同じ数値項目へ通常どおり加算する。例えば狙い撃ち3か国で犯罪+90、これに浸透2か国分があれば計+130。実際の犯罪表示等にengine側の上限・下限がある場合、それは別であり、表示が130になると約束するものではない。

## 効果表（v2の実装既定案）

| 種類 | 発生元 | 対象 | 1か国分の効果 |
|---|---|---|---|
| 狙い撃ち | tr_ngm_sniper | 発生国が指定した正式宿敵、または有効な架空宿敵 | 惑星犯罪+30 |
| 浸透 | tr_ngm_penetration | 発生国と接触済みの他のplayable国。味方・従属国も原版どおり対象 | 惑星犯罪+20 |
| 破壊工作 | tr_ngm_sabotage | 正式宿敵、または有効な架空宿敵 | 惑星犯罪+20、職業交易産出-15% |
| 報道の自由 | tr_ngm_freedom_broad | 正式宿敵 | 奴隷幸福度-20パーセントポイント |
| 恒常的妨害 | tr_ngm_constant_obstruction | 正式宿敵 | 職業交易産出-5% |
| 敵対的演説 | tr_ngm_battle_speach | 正式宿敵 | 外交発言力-10% |
| 恒常的敵対諜報活動 | ap_ngm_constant_hostile_intelligence_operations | 正式宿敵 | 基礎影響力産出-1／月 |

**交易部分は原版の同等移植ではなく、新しい効果の提案。** 未確認の「交易保護-15/-5」を捏造せず、実在する職業交易産出-15%/-5%に置換する。非職業産出の交易には掛からない。友人版の恒常的妨害の暗号化+5は、対外圧力の役割へ戻すこの案では外す。採用後は旧説明を必ず書き換え、両方を黙って付けない。ここは未実装の仕様案であり、既存MODへ適用した変更ではない。

%系は通常の加算modifierとして扱う。例えば3か国の破壊工作は職業交易産出補正-45%。全補正を乗算する「0.85の3乗」ではない。影響力や外交発言力などが大きく低下する可能性は、重複を認める仕様の結果として明示する。ゲーム内の計算下限は実測する。

## 対象と方向

発生元S、受け手R。SとRは別のplayable国。国の種類をdefaultだけに限定せず、Vanillaのevery_playable_countryが列挙する現存国を使う。植民地0という理由では除外せず、遊牧・移動中等の国を壊さない。

正式宿敵の判定はSからRへの `has_rival = R`。態度を調べる `is_rival` は使わない。RからSへの一方的な指定ではSのデバフは発生しない。

架空宿敵はS→Rの `ngm_pressure_v2_virtual_rival` relation flag。狙い撃ち・破壊工作にだけ適用し、他の種類へ無断で広げない。Sが悪徳採用を所持し、SとRが接触済みであることを毎回確認する。選択・解除はS側で `set_relation_flag/remove_relation_flag = { who = R flag = ngm_pressure_v2_virtual_rival }` を使う。全世界共有の番号は不要。

架空宿敵UIは既存の法令の選択・解除という流れを維持するが、選択一覧の対象はそのイベントチェーンのローカルevent targetで保持する。ページに16項目表示することと世界共通16枠を混同しない。世界共通枠は廃止する。正式宿敵指定をengineへ追加するものではなく、外交収入や宣戦・外交関係は変えない。自国・未接触・すでに選択済みの国を追加画面で除外し、解除画面には選択済み国だけを出す。UI上の選択と解除の両方で再集計を呼ぶ。

## 免疫

Rが `ap_ngm_ministry_of_innocence` を持つと7種類すべての計数を0にする。既に付いたv2補正も除去する。現存する別の内政ボーナスや宗主関連modifierは、このシステムがまとめて消さない。

免疫を持つSが他国へ発生させることは禁止しない。原版の免疫は受け手の防御だからである。後から免疫を失えば、その時点の関係から再計算して付与する。防御APを復旧する際は、誤った旧.25呼出しを戻さず、統一再集計へ接続する。

## 更新と処理構造

1. 受け手Rを同期チェーン内の `save_event_target_as = ngm_pressure_v2_receiver` に保存する。global targetを使わない。ROOT/FROMの内容へ依存しない。
2. Rの種類別count変数をすべて0へ初期化する。前月の数に加算し続けない。
3. Rが免疫でなければ発生元候補を1回走査する。各種類の所持条件とS→Rの関係を判定し、Rの対応countを+1する。
4. 種類別の既存v2補正を除去し、count>0の場合だけ `add_modifier` の `multiplier = count変数` で再付与する。count=0なら補正は残らない。
5. 補正は永久型とする。30日ごとに切れて付け直す方式をやめ、スクリプトで失効を管理する。

7種類すべてが当たる国でも、持つ補正インスタンスは最大7個。7種類×40か国分なら、最大280個をぶら下げるのではなく、最大7個に各count=40を渡す。効果量は40か国分で変わらない。

変数はRのcountry scope、走査中はSのcountry scope。Rへ値を戻すときは保存済みローカルevent targetへ明示的に戻る。planetsやpopsへ変更してからcountry用変数を操作しない。補正のcountryからColony/Popへの伝播と実数値は実機で検証する。

## フックと更新遅延

現行実ファイルにある `on_game_start` とglobalの `on_monthly_pulse` を入口に、全playable国をまとめて再集計する。countryごとのpulseが無い国もglobal列挙で更新できる。

`on_tradition_picked` と `on_ascension_perk_picked` はcountry scopeのフックとして実在を確認。取得後は全playable国を再集計し、発生源の新規取得と受け手の免疫取得の両方を反映する。架空宿敵の選択・解除後も同じ再集計を呼ぶ。

宿敵変更専用フックは現在の本体で確認できていないため作らない。正式宿敵解除、発生国滅亡、接触、特殊イベントによる伝統喪失、国の新生は遅くとも次の月次で反映する。即時解除を保証する仕様ではない。ロード専用フックも捏造せず、既存saveへの初回導入は次の月次で移行・再計算する。

初期版は稀な取得時にも全再集計を行う単純な構造で実装する。取得が同日に大量発生する大型銀河で重ければ、実在するglobal flagと遅延イベントによる更新予約の集約を別途追加する。初期実装に未検証の予約処理を混ぜない。

## 性能

1回の全更新はR国×S国の1走査で、各組に最大7種類の判定。50国で2,450組、100国で9,900組、200国で39,800組（自国分を除外）。100国なら最大約69,300種類判定／更新。これは計算量の見積りであり、ゲーム内処理時間の測定結果ではない。

番号ごとの巨大イベントを毎月多数走らせる現状より管理範囲が明確になるが、必ず高速化すると断定しない。まず複数の全国家走査を7本書くのを避け、1走査で7種類を数える。発生源キャッシュや国一覧の独自管理は、失効漏れを再導入しやすいため初期版では使わない。

## 既存save移行

実装順序を守る。

1. 旧月次.6/.8/.10/.12/.1012/.35/.26への接続を外す。
2. 伝統/APから旧初期化.5/.7/.9/.11/.1011/.34/.25を呼ばないよう置換する。旧IDは移行版ではno-opとして残し、保存済み呼出しに対して旧効果を復活させない。
3. 全countryから `legacy-cleanup-manifest.json` の63種類の旧対外補正だけを清掃する。非playable国に残ったものも対象。旧modifier定義は清掃完了を確認する移行版では保持する。
4. 元の共有global targetに依存する架空宿敵選択は、自動で新関係へ変換しない。保存先が他国に上書きされ得るため、元の意思を復元できない。旧選択は無効化して通知し、ユーザーに選び直してもらう。
5. 独自のglobal移行完了flagを記録し、全playable国を新方式で再計算する。旧番号flag・旧global targetは新処理から読まない。他MOD保護のため全global flag/targetの一括削除はしない。

移行完了flagがある場合も、通常の全再計算は止めない。移行途中save、初回の人口・国生成後の順序差、旧版へ戻した後の再導入は実機試験する。移行前saveのバックアップを推奨。安全な既存save対応を確認するまでは新規ゲーム推奨。

## 同時に必要な定義・連携の修正

- 悪徳・敵対の本体と採用・完成定義を復旧し、現在欠ける入口を解消する。伝統カテゴリの参照先欠落検査も通す。
- 防御APを復旧し、旧誤イベントを外す。既存AI weightは原版基準を維持する。旧8/15枠はAIにも人間にも適用しない。
- 恒常的妨害の暗号化+5を外し、この案の交易産出低下へ説明・実効果を揃える。
- 影響する日英翻訳、modifier名、伝統説明、防御AP説明を更新。採用UIと効果表示を一致させる。
- 善隣完成、国家宣伝省0宿敵時、宗主交代・独立時の清掃は別の支援効果同期として修正する。この対外圧力の受け手ループへ混ぜない。
- 自由完成の派閥影響力、未登録移民補正等は別の移植項目。圧力v2を有効にしただけで全伝統が直ったとは扱わない。

## 実装ファイルの分割

参考コアは `reference-core/` 内。ここはゲームが読むMODルートの外にあり、現在の開発版には読み込まれない。

- common/scripted_effects/NGM_pressure_v2_effects.txt：受け手の7種類集計・付与・解除。
- common/static_modifiers/NGM_pressure_v2_modifiers.txt：1か国分の基礎効果7定義。
- events/NGM_pressure_v2_events.txt：global更新とcountry取得フックの入口。
- common/on_actions/NGM_pressure_v2_on_actions.txt：確認済みの4フックへの接続。
- localisation/NGM_pressure_v2_l_japanese.yml：補正表示の日本語案、BOM付き。

統合時には上記に加え、移行effect・架空宿敵選択UI・失われた伝統/AP定義・英語翻訳を実装する。これらを揃える前に参考コアだけを稼働版へコピーしてはいけない。特に現在の開発版では一部の参照伝統と防御APが不在である。

## 根拠

4.5.2 engine出力文書で、`add_modifier` のcountry scopeと `multiplier = <float>/<variable>`、`set_variable/change_variable`、`has_rival`、`has_established_contact`、`set_relation_flag/remove_relation_flag/has_relation_flag` を確認。Vanilla `events/clone_army_events.txt:170` 付近にもvariableをmodifier multiplierへ渡す実例がある。

Vanilla `common/on_actions/00_on_actions.txt` にgame_start、global monthly pulse、tradition picked、ascension perk pickedが存在。7種類で用いるmodifierキーはすべて現在のmodifiers.logに登録されている。新しい独自定義名と変数名はNGMの名前空間として作るもので、未知のengine hookを追加するものではない。

## 検証・受入条件

参考コアの実ASTに対する限定評価20条件を `validation.json` に記録。発生国0/1/3/8/9/15/16/40、100回再更新で増殖しないこと、免疫取得/喪失、伝統喪失、宿敵解除、接触維持、発生国消滅、逆向き宿敵、自国除外、架空宿敵、正式＋架空で二重計数しないことを確認した。これはゲームエンジンの実行試験ではない。

統合後の必須確認：

1. 新規ゲームと旧saveの両方で最初のparser/script errorから確認。unknown trigger/effect/modifier、invalid scope、不在定義を0へ。
2. 1/3/9/16か国から同じ効果を与え、犯罪・奴隷幸福度・交易・発言力・影響力の実数値を比較。40か国は性能試験も行う。
3. 免疫取得で既存7効果が消え、免疫喪失後は関係に応じ再付与されること。
4. 旧63補正が残らず、月送り・セーブ/ロードで復活しないこと。
5. 宿敵解除、発生国滅亡、伝統喪失、AI取得、国新生、架空宿敵解除の各ケースで次月までに値が正しくなること。
6. 複数プレイヤーが架空宿敵を選び、相互に対象が上書きされないこと。正式指定と重複しても同一発生国は1回。
7. 旧版・新方式の同じ銀河で月送り時間を比較する。処理時間の劣化があれば取得時更新を集約し、再度失効テストを通す。

今回の作業は仕様と参考実装の準備であり、Vanilla overrideの追加も、稼働版のゲーム処理の変更もない。交易置換は意図的な仕様案として明示し、実機未確認のscope伝播・数値下限・性能を確認済みとは扱わない。
