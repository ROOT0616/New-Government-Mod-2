# 旧コードの改善・最適化案

調査日: 2026-10-23。対象: 原版 master d54857b、友人版、開発版 1.39.0-dev.19。実装判断の基準はインストール済み Stellaris Cygnus 4.5.2 (9776)。今回は調査・提案のみで、ゲーム用ファイルは変更していない。

## 結論

改善できる。優先すべきなのは、戦争終了などの「現在の状態を正しく反映できない処理」の修正、月次処理の重複削減、巨大な選択肢の生成・管理方法の整理である。

旧版には当時の仕組みに合わせた実装もある。古い書き方という理由だけで欠陥とは扱わない。また、復旧時に追加した移行処理・毎月の再計算にも改善余地があり、以下では出自を分ける。性能の数値は実測しておらず、行数や走査回数から速度向上率を算出することはできない。

## 1. 逆境の補正は、最適化より先に正しさを修正

根拠: `events/NGM_tradition_event.txt` の `ngm_tradition.1001` / `.1002`、`common/on_actions/NGM_on_actions.txt`。

開始イベントは防衛戦争中なら補正を追加する。終了イベントも「まだ戦争中で、防衛側の戦争が存在する」を条件にして補正を削除する。このため、最後の戦争終了後には条件不成立で削除されない経路があり、別の防衛戦争が続いている間に削除してしまう経路もある。終了hookの対象も全参加国ではなく、コード上のコメントでは敗者をRootとしている。

改善案: 「伝統を持ち、現在も防衛戦争に参加しているなら追加。それ以外なら削除」という一つの同期処理にする。開始・終了時に必要な参加国へ同期し、月次は修復用にする。終了hookの実scopeと参加国の取得方法は4.5.2の実装を確認して確定する。

検証: 単独防衛戦争の勝敗、二つの防衛戦争の片方だけ終了、攻撃戦争のみ継続、同盟参加、伝統取得・喪失、セーブ読込。既存saveは残留補正の掃除を一度行う。

## 2. 罰金制度は50段階を保ったまま更新回数を減らせる

根拠: `common/scripted_effects/NGM_civic_economy_effects.txt` の `ngm_sync_money_penalty_effect`。

現在は毎回50種類の旧modifierを削除し、50段階それぞれで犯罪値と国是を判定し、不要depositを削除する。階段式の効果自体を廃止する必要はない。

改善案: 国是の有効性を入口で判定し、犯罪値から必要段階を一度決める。前回適用段階と同じなら終了し、変わった場合だけ旧段階を削除して新段階を追加する。既存saveの複数depositや旧modifierは版数付き移行で一度掃除する。状態記録と実depositが食い違うケースには読込時・所有者変更時の修復を用意する。

注意: 犯罪0、整数境界、50以上、国是無効化、惑星譲渡で現在の値を保つこと。使用する丸め・値計算方法は現行Vanillaの実例を確認して決める。未確認の計算構文は導入しない。

## 3. 月次の旧デバフ掃除は、復旧版側の改善点

根拠: `common/scripted_effects/NGM_pressure_v2_migration.txt`。

全体の初回移行完了flagはあるが、その後の毎月の playable country 巡回でも `ngm_pressure_v2_migrate_country_effect` を呼ぶ。その中で63個の旧補正、16個の旧選択flag、旧カウンタを毎回掃除する。これはユーザーの原版ではなく、今回の復旧で追加した処理の改善点である。

改善案: 各国に移行版数を持たせ、未移行国だけ実行する。新規出現国や解放国も処理できるようにする。旧イベントの予約発火は互換stubで受け、毎月全掃除する必要をなくす。大規模な再修復は版数更新時に限定する。

## 4. 対外圧力は「集計」と「適用」を分ける

根拠: `NGM_pressure_v2_effects.txt`、`NGM_pressure_v2_support.txt`、`NGM_pressure_v2_events.txt` と関連on_actions。

現行は受け手ごとに他国を走査し、7系統を集計する。その後、値が変わっていなくても補正を削除して追加する。全体更新では国数Nに対して概ねN×Nの関係確認となる。伝統・AP取得時にも全体同期する。

改善案は段階的に行う。

1. まず集計は維持し、前回の適用値と変わった補正だけ更新する。値0でも実際に残留補正があれば削除する。
2. 圧力を発生させる伝統・APを一つも持たない国の詳細判定を省けるか調べる。
3. 関係する伝統・AP取得や仮想宿敵変更は対象を限定して同期する。毎月の全体同期は外交変化・国家消滅等の取りこぼし修復として残す。
4. 実測後に、必要なら発信国中心の集計方式を比較する。方式を変えても最悪時の全関係確認が必ず消えるわけではない。

同じ効果を複数国から受ける仕様は維持する。重複上限を追加しない。免疫解除、接触喪失、発信国消滅、正式宿敵と仮想宿敵の重複、伝統喪失を検査する。支援省の影響力補正も同様に変更時更新へ揃えられる。

## 5. 巨大な前衛主義メニューは「手書き」を減らす

根拠: `events/NGM_tradition_event.txt` は13,425行。構文解析では `.4` だけで1,915構文ノードを持ち、国是判定と変数操作が大量に並ぶ。ページごとの国是選択にも似た条件・適用処理が反復する。これはノード数であり実行時間ではない。

改善案: 国是ID、表示順、必要条件、適用処理を一つの一覧で管理し、開発時にページ・選択肢を生成する。ゲームへ配布するのは通常のイベントファイルとする。実行時に動的UIや動的キー参照が可能だと仮定しない。共通化できる適用処理はscripted effectへ移すが、Root/Fromと引数の扱いを確認する。

現在は対応する前衛主義の伝統定義が未復旧で、通常の取得経路から使える機能としては扱えない。したがって、ここは当面の月次性能問題よりも、再復旧時の保守性・条件整合性の改善候補である。旧saveの参照を考慮し、既存イベントIDは安易に変更しない。

## 6. 惑星同期は入口を共有し、効果ごとの責務は残す

根拠: 経済、国是職業、倫理職業、民兵、戦争経済等がそれぞれ開始・月次・植民・所有者変更に接続している。静的抽出では月次hook定義ブロックが13個ある。ただし、これは13回の全銀河走査を意味しない。国単位hook、全体hook、イベントtriggerによる早期終了を区別する必要がある。

改善案: 国単位で同期が必要な機能を判定し、一回の所有惑星巡回から各planet effectを呼ぶ。植民・譲渡は当該惑星だけ即時同期する。機能別effectは残し、巨大な一枚のイベントへ戻さない。

国是を持たない国を単純に除外すると、国是変更・併合後の古いdepositが残る。適用中の状態も入口条件に含め、削除が必要な対象を巡回から外さない。

## 7. リーダーは適用対象と一度限りの処理を明示

根拠: `NGM_civic_leader_effects.txt`、`NGM_remaining_civic_effects.txt`、関連イベント。現在はflagにより初回効果を制御する一方、所有者・候補者の巡回が複数経路に分かれる。若年・長老の年齢変更は、未処理の外部雇用者やイベント由来リーダーにも及びうる。

改善案: 「生成時の年齢設定」「雇用候補への初回付与」「現在の国是に応じた常時補正」「月次の不足修復」を分ける。外部雇用者・パラゴン等を含めるかは国是の仕様として決める。適用済みflagは効果別に維持し、同じ一括flagで別の効果まで抑止しない。国是廃止後も残す特性と解除する補正を一覧化する。

原版の根本的狂気には既存maniacalを上位へ進める分岐があるが、現行補助処理は未所持者へ初段を付与する形である。これは速度の問題ではなく効果差なので、「一度だけ昇格させるのか、最低等級を保証するのか」を決めてから直す。月次で際限なく昇格させない。

## 8. 職業置換と適性は別々に整理

根拠: `NGM_civic_ruler_jobs_effects.txt` と関連deposit/script value、`common/pop_jobs/NGM_pop_jobs.txt`。

国是×首都段階の職業数と政治家減少数を複数箇所で管理すると、片側だけ修正しやすい。国是併用時は独自職業の加算と政治家減少上限の関係を確認する必要がある。置換対象がVanillaの別職へswapする帝国も検証対象になる。

改善案: 国是ごとの職業置換表を一つ作り、deposit容量・政治家減少値・検証ケースを同じ表から生成する。複数国是の加算を認めるか、排他にするかは仕様として明記する。

また、現行の儀典局職にも研究系の特性を優遇する評価が含まれる。職業の出力と一致する適性を個別に設計する。研究職・行政職・交易職・軍事職を一律のweightで統合するのは避ける。これは復旧時の再構成についての改善点である。

## 9. Vanilla上書きは「短くする」より「必要部分を明確にする」

対象: `common/policies/00_policies.txt`、`common/pop_faction_types/00_traditionalist.txt`、`common/economic_categories/NGM_categories.txt`、倫理選択GUI等。

政策・伝統主義派閥には旧定義が残っている。economic categoryには独自職業用とVanilla名の定義が混在する。これらは単なる重複削除ではなく、現行Vanillaで増減した選択肢・条件・カテゴリ階層を追跡してから整理する必要がある。

改善案: 4.5.2の該当定義との機能差分表を作る。独自定義で拡張できる部分は分離し、同名上書きが必要な部分は現行定義を基準にNGM条件を加える。カテゴリを削除する前に、生成modifier名・継承・全参照元を確認する。GUIは倫理追加に必要な上書き範囲を維持し、更新時の差分検査を用意する。

政体の大半の旧Vanilla上書きは既に整理済みである。この項目を「全政体が未対応」と解釈しない。

## 10. 倫理・評議員などの反復定義は安全に共通化

原版には通常・狂信倫理間で似た魅力条件、評議員間で似た資格条件が反復する。完全に同じ条件はscripted trigger等へ抽出するか、生成元を一つにできる。ただし、見た目が同じでもpop/country/leaderのscopeやAI weightの意味が違う箇所は共有しない。

改善案: まず構文木で同一部分を抽出し、頻度と修正履歴から共有対象を選ぶ。評議員のクラス・国是・倍率、倫理の対象scopeはデータ表に残す。定義数を減らすこと自体を目標にせず、更新箇所と検査項目を減らす。

## 11. 原版との差を仕様表で追う

既存の構文・参照検査に加え、機能ごとに「対象、条件、数値、加算方法、更新時点、解除条件、AI条件、原版との差」を記録する。現行化による意図した変更と、単純な復旧漏れを分離できる。

特に、第19段階の移住・降格・犯罪・建造関連の代替効果、複数資源の職業補正の平均化は、未知キーの解消だけで元の体感まで等価になるわけではない。少数の代表帝国で実際の生産・移住・職業配置を比較する。復旧済みの旧modifier問題を未修正として再計上しない。

実装後の検査は、構文確認→状態遷移テスト→実機error.log確認→同条件saveの月次時間比較の順にする。性能比較は同じ銀河・日付・国数・惑星数で複数回行う。自作の構文評価器の合格をStellaris実機合格とは扱わない。

## 実装するならこの順序

1. 逆境補正の追加・解除を修正し、既存saveの残留を修復。
2. 国単位の版数付き移行と、対外圧力の変更時更新。重複加算は維持。
3. 罰金段階の変更時更新。境界値と国是解除・譲渡を検査。
4. 惑星・リーダーの同期入口を整理。月次修復は取りこぼし対策として残す。
5. Vanilla上書きの現行化、職業適性と原版効果差の調整。
6. 未復旧機能を復活させる段階で、前衛メニュー等を一覧から生成する構成へ変更。

## 今回の範囲・互換性

- ゲームの実装変更なし。バージョンは1.39.0-dev.19のまま。
- 新たなVanilla overrideなし。今回の文書追加自体には競合・saveへの影響なし。
- 提案を実装する際はイベントID、特性ID、deposit名を安易に変更せず、必要な移行処理を設計する。最適化案だけで一律に「既存save安全」とは判断しない。
- 技術取引・艦隊贈与は別MOD化済みのため、復旧・最適化対象から除外。
- 原版・友人版・Vanilla・sourcesは変更していない。
- NGM実機起動、処理時間計測、全AI挙動の確認は未実施。今回の構造調査は `audit_optimization.py` と `optimization-inventory.json` に保存。
